# Fox Trot 作業規範

這份文件是審查站與內容製作的完整規則，與 `quality.html`、`workflow.html`、README 對齊。品牌是虛構的，審查站只供內部品質控制，內容不得發布到任何社群平台。

## 1. 品牌與語氣

- 品牌名稱固定寫成 **Fox Trot**（中間分開、只用英文），不要寫成 Foxtrot 或 FoxTrot（帳號 handle 除外）。
- 狐狸只以很小的腳印記號出現，不要做成完整吉祥物或 wordmark logo。
- 定位：跑得久，比跑得快更重要。
- 語氣：輕鬆、明快、簡潔有力、幽默。
- 語言：繁體中文、台灣用語。受眾是一般大眾到中輕度跑者。
- 品牌強調色是橘色 `#FF7A1A`，不要用紅色。

## 2. 產出節奏：一次一週，不排程

- 每日 routine 已經關掉，不再重開，也不再按日自動排程。
- 等 Alfred 開口時，一次產出一週份（7 則）。
- 七則依 **A → B → C** 循環排列，每則標上「預定發布日」（連續七個曆日）。
  - A：傷害預防與恢復
  - B：賽事資訊（台灣近期可報名的路跑、越野賽）
  - C：訓練知識白話版
- B 日列出的賽事，報名截止日必須**晚於**該則的預定發布日。已截止、或在預定發布日當天截止的賽事不要放。
- 不要在對話裡先預覽草稿。研究、寫文、配圖、自我檢查完成後，直接推上審查站等審查。

確認流程後，才產出第一批一週份。未獲確認前，不要自行開始週批次。

## 3. 審查在審查站進行

- 每則有穩定編號，自 `FT-001` 起編，後續依序遞增，不重複使用已分配的編號。
- 現有編號：
  - **FT-001**：2026-11-11 每日五平台（A 日，傷害預防）
  - **FT-002**：2026-11-12 每日五平台（B 日，賽事資訊）
  - **FT-003**：2026-11-12 Instagram 輪播「新手跑者常見的 5 個傷害警訊」
- 狀態只有三種：**待審**（`pending`）、**通過**（`approved`）、**退回**（`returned`）。退回必須寫上原因。
- 版次以整數計（顯示為 v1、v2……）。首次上審查站的版本為 v1；若上站前已有清楚記錄的預覽輪次（例如輪播四次改版），可接續該紀錄（FT-003 因此為 v4）。對話裡更早的圖片風格試驗，若未當成正式預覽輪次，不算站上版次。
- 每則保存 `reviewHistory`：日期、版次、狀態、原因或意見。
- 審查方式：Alfred 看完審查站後，在對話回覆「**編號＋結果＋意見**」。代理人依這則回覆更新狀態與審查紀錄，不必猜。
- 修改後的版本：版次加一，狀態回到「待審」，並在紀錄寫明改了什麼。
- 首頁必須一眼看出哪些還在待審：審查進度（各狀態筆數＋待審清單）放在目錄之前。
- 即使狀態改為通過，也還是不得發布到任何社群平台。

## 4. 只做五個社群平台

每日則只做：

1. X
2. Threads
3. Instagram
4. Facebook
5. LinkedIn

- 已不再做網頁文章。舊的「每日六平台」改稱「每日五平台」，資料 `type` 為 `daily-5`；舊的 `daily-6` 僅作為相容別名。
- 五個版本要依平台改寫，不是同一篇剪短。
- Instagram 輪播只做輪播與 caption，不假裝已有其他平台版本。
- Threads 建議 500 字元內；X 建議 140 個中文字內；Instagram 附 5–10 個 hashtag。
- 檔案路徑維持 `posts/YYYY-MM-DD-daily.html`、`posts/YYYY-MM-DD-ig-carousel.html`，舊網址繼續可用。`#type=daily-6` 視為 `#type=daily-5`。

## 5. 研究數字與免責

- 研究數字寫成白話，例如「風險明顯比較高」。危害比、信賴區間、樣本數、精確百分比等原始數據放在來源附註，不寫進貼文。
- 「觀察關聯，非因果」不要在每個平台一字不差地重複。每一則說一次即可，用自然口語，例如「這是研究看到的趨勢，不是保證」。各平台說法可以不同。
- 「疼痛持續請看醫師或物理治療師」在傷害相關內容裡照舊保留，語氣可自然調整，意思不變。
- 不做診斷、不保證療效，不把觀察到的關聯寫成因果。

## 6. 來源規則

- 只列出真正打開過的原始來源，不編造數字，不誇大結論。只讀到摘要或 bottom line、沒有打開全文，必須註明。
- 來源只用官方、機構、媒體或研究。
- **不連結個人帳號**：X 或其他社群上一般人的貼文，最多只能拿來觀察話題，不列入來源清單、不附連結、也不寫出帳號。
- 不引用 NHS Inform PFP（該頁曾無法開啟核對）。

## 7. 品管清單（七項）

每則上站前須檢查（或不適用並說明）：

1. 傷害與醫療相關用詞
2. 賽事資訊（含 B 日截止日必須晚於預定發布日）
3. 研究引用與結論分寸（含白話數字、原始數據放附註）
4. 圖片限制
5. 是否依平台調整
6. **場景季節要對**：配圖符合台灣該月份實際景況。例如 11 月宜蘭水田是休耕或收割後，不會有剛插的秧苗。
7. **不連結個人帳號**：見第 6 節。

詳細條文見 `quality.html`。

## 8. 圖片規則（摘要）

- 自行產出的寫實紀實風照片，再由程式排上中文標題。不使用他人照片。
- 圖上中文必須用已安裝的 CJK 字型排字（目前為 Noto Sans CJK TC Bold，`/usr/share/fonts/opentype/noto/NotoSansCJK-Bold.ttc` index 3），不要讓圖像模型生成文字。
- 畫面不能有真實或虛構的品牌標誌、可讀文字、可辨識的臉、畸形肢體或誤導性傷勢。
- 台灣場景不靠破舊公寓或罐頭街景來證明「這是台灣」。構圖要有變化。
- 新聞卡是「上方照片、下方深色文字面板」。輪播除封面外每張都要有自己的、對得上文字的照片。
- 產生後在完整尺寸與約 360px 寬各看一次，有疑慮就捨棄，不要修掉 logo 再上稿。
- 季節必須正確（見第 7 項第 6 條）。

## 9. 工作邊界

- 不把任何內容發布到社群平台。
- 不開設、也不使用真實的社群帳號來代表 Fox Trot。
- 不花錢：不買廣告、不付訂閱、不為了產出內容付費下單。
- 未經明確同意，不代為對外寄信或傳訊。
- 不使用或要求使用 Alfred 的個人帳號去發布或登入社群。
- 不重開每日 routine。

## 10. 技術備註

- 資料寫在 `data/days.js`。必要欄位：`reviewId`、`date`、`cycle`、`plannedPublishDate`、`status`、`version`、`reviewHistory`、`type`（`daily-5` 或 `ig-carousel`）。
- 每次上線須改 `scripts/build_review_site.py` 裡的 `ASSET_VERSION`，再執行 `python3 scripts/build_review_site.py`。
- 生成的 HTML 視為產出檔，不要手動改。關掉 JavaScript 也應能讀到正文、來源、狀態、審查紀錄與圖片。
- 倉：`foxtrot-run-tw/foxtrot-review`。直播址：https://foxtrot-run-tw.github.io/foxtrot-review/
