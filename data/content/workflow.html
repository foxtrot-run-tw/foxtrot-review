怎麼做的

工作流程

這頁說明審查站現在怎麼產出與審查內容、用了哪些工具，以及圖片方向與 Instagram 輪播的改版紀錄。方便一起上來查看的人（包含協助審查的 Claude）對齊同一套作業方式。

怎麼產出：一次一週、七則

每日 routine 已經關掉，不再重開，也不再按日自動排程。改成 Alfred 開口時，一次產出一週份（7 則）。

  1. 依 A → B → C 循環排七則。 A 是傷害預防與恢復，B 是台灣賽事資訊，C 是訓練知識白話版，然後再回到 A。每一則都標上「預定發布日」（連續七個曆日，對應開口後要排的那一週）。
  2. B 日賽事要檢查截止日。 列入的賽事，報名截止日必須晚於該則的預定發布日。已經截止、或在預定發布日當天就截止的，不要放進該則。
  3. 研究題目與來源。 依該則主題找出需要打開的官方頁、衛教或研究文獻。只採用真正打開過的網址；數字、日期、報名期限與結論分寸都依原頁。沒打開全文就註明。
  4. 依五個平台寫文案。 每日五平台分別寫 Threads、Instagram、Facebook、LinkedIn、X，不是同一篇剪短，也不再寫網頁文章。研究數字用白話，原始數據放來源附註。因果免責每則用口語說一次即可，各平台說法可以不同。傷害相關內容保留「疼痛持續請看醫師或物理治療師」。輪播實驗則集中寫圖上短文與一則 caption。
  5. 產出照片候選並排字。 用 AI 圖像生成寫實紀實風照片，場景季節必須符合台灣該月實際景況。有 logo、可讀文字、怪手怪腳、可辨識的臉、結構畫錯、季節不對或不對題的圖會直接捨棄。再以 Python 與 Pillow 把標題排進新聞卡，字型用已安裝的 Noto Sans CJK TC Bold，重點字是橘色 #FF7A1A。
  6. 自我檢查。 對七項把關原則逐條看過，並在完整尺寸與約 360px 寬檢查文字是否仍清楚、圖片有沒有違規。
  7. 直接推上審查站。 草稿不先在對話裡預覽，編好編號（例如 FT-004）、狀態「待審」、版次與審查紀錄後，生成靜態頁並推到 GitHub Pages。內容仍然不是社群發布。

怎麼審查：在審查站上進行

  1. 每則有穩定編號（FT-001、FT-002……）、狀態（待審／通過／退回）、版次（v1、v2……）與預定發布日。退回必須寫上原因。
  2. Alfred 看完後，在對話裡回覆「編號＋結果＋意見」，例如「FT-002 退回，截止日請再核對官方頁」。代理人依這則回覆更新審查站上的狀態與審查紀錄。
  3. 若需修改：改完後版次加一，狀態回到「待審」，並在審查紀錄寫明改了什麼。通過後才視為定稿；即使通過，也還是不會發布到任何社群平台。
  4. 首頁最上方的「審查進度」會列出目前有幾則待審、通過、退回，以及待審清單，讓人一眼看到還要看哪些。

使用的工具（白話）

  • AI 圖像生成： 用來產出紀實風照片候選，不負責圖上的中文標題。
  • Python 與 Pillow： 把選定的照片裁切、漸層、排字，組成 4:5、16:9 或 1:1 的新聞卡，以及 Instagram 輪播。
  • 靜態網站與 GitHub Pages： 審查站沒有建置伺服器端程式，頁面由腳本先生成 HTML，再放到這個 GitHub 倉的 Pages。倉是審查用帳號 foxtrot-run-tw 底下的 foxtrot-review，不是 Alfred 的個人社群帳號。

各輪大約花多久

第一天（2026 年 11 月 11 日）從研究、寫當時的六個平台版本、建審查站，到多次改圖片方向與換成橘色，是分成好幾段完成的，不是單一輪的七分鐘就能做完。後來平台已改為五個社群版本，不再含網頁文章。

之後較能對照的單輪時間大致如下（皆為台灣時間）：

  • Instagram 輪播各次改版，大約每次 4 到 7 分鐘。例如第三次改構圖與河堤約 4 分鐘，第四次讓每張圖對上文字約 7 分鐘。
  • 輪播通過後，把它加進審查站並加上版型篩選，大約 7 分鐘。

這些時間指的是「這一輪修改與產出」，不含稍早已經做完的研究與文案。

圖片方向怎麼演進

  1. 最早試過孔版／Risograph 風格的插畫風配圖。
  2. 改成寫實紀實照片，再由程式排成新聞卡（上方照片、下方深色面板與大標題）。
  3. 依回饋加入人物，並讓場景更接近台灣會出現的風景；同時放大副標與以下層級的字。
  4. 品牌強調色從紅色改成橘色 #FF7A1A，並更新已上線的審查頁。
  5. 輪播第一版曾把其中幾張改成文字為主、照片只留窄帶，被指出跑版（字跑到上方把圖遮了大半），之後全部改回「上圖下文」。
  6. 再來修掉畫錯的河堤、拿掉用來暗示「這是台灣」的破舊房子，並讓構圖有半身、特寫與無人場景的變化，不再連張都是全身背影。
  7. 風格通過後，再要求每一張輪播的照片必須清楚對應那張的文字，不能只是氣氛圖。
  8. 之後補上季節規則：11 月 12 日那則原先的宜蘭水田出現剛插的秧苗，不符合 11 月休耕期，已整組換成休耕／收割後的場景。

Instagram 輪播的四次改版

題目是「新手跑者常見的 5 個傷害警訊」，共八張、4:5、1080×1350，只做 Instagram，沒有發布。此則編號 FT-003，審查站上的版次接續對話預覽的四輪，標為 v4。

  1. 第一版： 建立八張輪播與文案。其中第 3、7、8 張用了偏文字的版型；有些照片重複使用。
  2. 第二版： 回饋指出第 3、7、8 張跑版，且除封面外每張圖應該不同。於是全部改回上圖下文，並讓各張使用獨立照片。當時構圖偏重複，場景也還有不少房子。
  3. 第三版： 回饋指出第四張的河堤幾何完全畫錯，而且前面幾張不需要靠破舊房子來代表台灣，人物也不必都是全身背影。這輪改掉河堤、拿掉無關的舊公寓，並變化構圖。圖片風格在這版獲得通過。
  4. 第四版： 回饋是「圖片沒問題了，但是多數圖的內容跟文字完全沒關聯」。這輪讓封面、五個警訊、清單與行動呼籲的照片都對上各自的文字（停跑按膝、步伐走樣、按脛骨、愈跑愈痛而減速、夜間冰敷、下樓按膝前側、坐下檢查、收操慢走）。此版通過後，才放上審查頁。後來依作業規範補上編號與狀態欄位時，圖文沒有再改，仍為 v4、待審。

第四版仍有一個已知限制，寫在該則的自我檢查裡：第 2 張（步伐走樣了）看得出人在跑道上移動，但跛行幅度比較含蓄，不是非常明顯的一腳代償。

以後要新增多則時

依開口一次寫入一週七則（或依回饋修改既有則）。在 data/days.js 追加資料，指定 reviewId、status、version、plannedPublishDate 與 reviewHistory，必要時把新圖放到 images/，把 ASSET_VERSION 改成新值，然後執行：

python3 scripts/build_review_site.py

腳本會重寫首頁目錄、審查進度與各則靜態頁。先本機打開檢查（即使關掉 JavaScript 也應能讀到正文、來源、狀態與圖片），通過後再提交。完整規則見 作業規範與倉裡的 README。
